本地起点与 GitHub 远端 HEAD 一致。桌面原 APK 的包名为 `com.caixukun.paodoubp`，版本为 `v2.3.0 / 20300`。界面与存储改进发布为 `v2.4.0 / 20400`；更新回退机制发布为 `v2.4.1 / 20401`。

## 已实现

### 首页与路线库

- 首页改为整页滚动，按“绘制—运行—管理”组织入口，突出绘制操作。取消双列卡片的固定高度，降低小屏和大字体下的文字裁切风险。
- 保留深色配色，减弱通用卡片边框、提高辅助文字亮度。定位权限和模拟位置配置分别呈现，配置完成时收起操作提示。
- 路线库增加路线数量、可直接输入的搜索框、加载进度、失败重试和不同的空状态。
- 底部提供带文字的“导入”和“绘制新路线”按钮；列表卡片使用两列两行操作，替代四个挤在一行的按钮，最小高度为 48dp。
- 搜索时更新现有 Adapter，不再重复设置 ListView 的 Adapter；复用 ViewHolder，并跳过相同列表的无效刷新。
- 删除确认包含路线名称；搜索关键词保留于页面重建。

### 逻辑与可靠性

1. **修复导出异常**：原先 `ShareUtils` 使用 FileProvider，但 Manifest 未注册。现已注册与包名一致的 authority，限定只共享内外部 `routes/` 目录，并随 JSON URI 提供临时读权限。
2. **避免同名覆盖**：保存和导入遇到同名文件时生成独立文件；编辑保留原 ID 和创建时间，重命名不再影响已有 ID 引用。
3. **减少写入中断的数据损坏风险**：先写同目录临时文件并同步，再进行原子替换。若文件系统不支持原子移动，操作会失败，不降级为覆盖旧文件。
4. **输入边界**：文件读写限制为 8 MiB；导入至少需要两个点，坐标必须有限且处于合法经纬度范围。拒绝越界文件 ID 与指向目录外的符号链接。
5. **路线库后台 I/O**：读取、导入、删除由 ViewModel 的串行工作线程处理，状态通过主线程发布。请求跨页面旋转保留，页面销毁后不会操作旧 Activity；导入不会因同时刷新而被丢弃。
6. **更新检查**：从“每个已安装版本只自动检查一次”改为“成功检查后间隔 24 小时再检查”，失败不占用间隔；连续点击不重复排队，销毁后的页面不再展示更新弹窗。
   GitHub 匿名 API 被限流时会读取仓库根目录的 `update.json`，并使用固定的 latest-download APK 地址。
7. **Android 9 搜索兼容**：原拼音转换在静态初始化时调用 API 29 方法。现在按版本延迟初始化，Android 9 保留中文原文和英文匹配；Android 10 及以上支持拼音和首字母。转换结果使用最多 256 项的缓存。
8. **Android 15/16 主题与系统栏**：移除意外覆盖成浅色的版本主题，在 BaseActivity 统一处理系统栏、刘海和输入法 Insets。

## 建议的后续顺序

### 优先：真机验收与运行状态归属

在 Android 9 和 Android 15/16 上验证首次权限拒绝/恢复、小屏大字体、键盘展开、导入后返回、导出分享、旋转和后台运行。尤其需要确认 `RouteRunActivity.onDestroy()` 会调用 `stopSimulation()`：若目标是旋转或页面重建后继续运行，应将运行会话交由前台 Service 持有，Activity 只订阅状态。改造时补生命周期测试，明确用户主动停止与系统回收的区别。

### 其次：继续拆分运行页与消除剩余阻塞

`RouteRunActivity` 当前约 4207 行，同时管理地图、参数、运行、悬浮窗和提醒。建议按“运行会话、地图交互、悬浮窗、配置”逐步抽离，先保持外部行为不变。`RouteRunViewModel.refreshRoutes()`、按 ID 选择路线和绘制页仍有全量读取路径，可沿用本次路线库的后台处理方式，并增加按 ID 直接读取，避免为了一个路线解析全部文件。

### 其次：让单个损坏文件不影响整个路线库

当前 repository 的全量读取遇到任一损坏 JSON 仍会报错。下一步建议返回“成功路线 + 失败文件名”的结果，允许用户导出或删除坏文件；不要静默跳过后让用户误以为数据丢失。路线数量增多后，再用实际耗时决定是否增加摘要索引或数据库，避免过早引入缓存一致性复杂度。

### 发布前：清理遗留配置与质量门槛

逐步清理不可达的旧布局、共享/NFC 等遗留资源和代码路径；统一源码目录与 Java package，核对 MissingClass。确定中文优先还是完整双语，再有针对性地补齐翻译。处理可达路径的权限检查和系统版本兼容问题后，建立 Debug 构建、单元测试、Lint 和 Release/R8 的 CI 门槛。发布时递增版本号并同步 GitHub Release 标签。
